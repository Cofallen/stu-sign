# 键盘控制轮腿机器人

直接运行最外层 `controller.py`：自动打开窗口、开启键盘控制，持续仿真直到关闭窗口。**不用再选 --viewer/--drive，也不会十秒后留下冻结画面。** 其它 Python 文件仍集中在 `LQR_six/`。

```bash
PYTHONNOUSERSITE=1 /home/cofallen/miniconda3/envs/mjlab/bin/python -B controller.py
```

点击一下 3D 窗口使其获得焦点。左下角 `RUNNING t=... x=...` 是实际仿真时间/位置，应持续变化；不是只看关节小数点。

| 按键 | 操作 |
|---|---|
| W / S | 速度每次加/减 0.1 m/s，范围 ±0.4 m/s |
| A / D | 左/右转，0.2 rad/s |
| Q / E | 缩腿/伸腿，每次 0.02 m，范围 0.22–0.30 m |
| J | 停稳后跳一次：下蹲→蹬地→腾空→落地 |
| X | 停车、停止转向 |
| R | 恢复默认速度/转向/腿长目标，不瞬移机器人 |

键盘命令是锁存式，按一次后持续执行，**X 停车**；不是松开即停。跳跃前先 X 并等车停稳。关闭窗口结束。已有窗口不会自动热更新，改代码后要关闭再启动。

## 轮子、地面与鼠标

- 轮子外观已恢复随模型提供的左右轮 STL；半径 0.06 m 的圆柱只作隐藏碰撞。没有用圆柱代替源外观，也未修改正式完整闭链、惯量、关节轴或原 XML。
- 使用运行时派生的浅灰棋盘地面，便于观察滚动和位移，不改变地面碰撞/摩擦。驾驶时隐藏左右调试面板，并保持显示设置，避免 W/J/X 等键同时触发 MuJoCo 原生的线框/关节轴/透明显示。
- 鼠标普通拖动是在移动相机；对机器人施力需先双击选中机身，再按 Ctrl 拖动。见 [MuJoCo 官方操作](https://mujoco.readthedocs.io/en/3.3.1/programming/samples.html#simulate)。窗口模式保留 GUI 施力，不每步清零；键盘平衡控制仍持续工作，不需要改 Joint/Control 面板小数值。

## 已实际检验

真实桌面窗口、XTest 实际按键验证了默认无参数启动：W 使机身移动约 1.32 m，Q/E 对应实际腿长变化，J 双轮腾空约 0.24 s、机身最高比起跳前高约 12.7 cm，落地后保持平衡；仿真持续超过 10 s，并由关闭窗口正常退出。不是只调用按键函数或改 qpos 做动画。数据/截图/失败范围见 [REPORT.md](REPORT.md)。

后续鼠标自动化在切换焦点时报错，该项没有完整通过的定量鼠标拖动证据；没有把它当成功。保留 GUI 外力的代码与物理扰动测试是分开的证据。

## 文件与依赖

`controller.py` 是唯一日常入口；`LQR_six/` 保留作者六状态 LQR/PID/VMC 链，`teleop.py` 只产生目标和跳跃阶段，跳跃额外支撑力仍由六个真实电机通过 VMC 输出，限幅不变。`render_stand.py` 负责源轮外观/地面/相机。`assets/` 包含两 XML/24 STL/manifest，`standing_pose.json` 只用于 reset；输出进入自身 `outputs/<新运行ID>/`，不覆盖历史。

使用已有 Python/MuJoCo/NumPy/SciPy，版本见 requirements.txt。不自动安装依赖、不修改驱动/环境，不需要父工程包。相对路径以入口所在目录解析，可以连同资产复制。原作者来源和具体差异见 SOURCE_MANIFEST.json、SOURCE_CHANGES.patch、THIRD_PARTY.md。

仅检查数值时用 `--headless --duration 10`；旧视频/相机/对照参数保留兼容，但不作为日常操作入口。

当前跳跃是平地仿真下的定时动作，未做地形/实机验证。轮子离地空转时编码器里程计不再等于机身位移，日志同时保留实际机身位置/接触/轮角；未声称飞行时定位正确。窗口仍可能慢于实时，但 RUNNING 时间应持续前进。没有 GPU/Isaac、训练、跨机器、实机或长期驾驶验收。
