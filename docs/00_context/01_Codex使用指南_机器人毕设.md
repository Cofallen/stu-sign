## 4. 用 AGENTS.md 保存长期约定

Codex 支持通过 `AGENTS.md` 提供项目指导；项目路径上的文件按层级加载，较近目录的指导可覆盖上层指导。它适合保存环境、验证要求和科研约定。[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

下面是供你后续采用的内容示例，本次没有自动创建或改变项目规则：

```markdown
# 项目约定

- 用中文解释，保留必要的英文术语。
- 先读取 README 和适用的项目说明，再提出修改。
- 区分论文报告、本地日志、推测和待验证假设。
- 每条文献给出可核对链接；不得编造实验结果。
- 选题阶段只写文档，不启动训练或修改依赖。
- 开展训练前先确定环境、时长、显存和结果目录。
- 每次实验保存配置、随机种子、代码版本和日志。
- 不覆盖旧 checkpoint，不删除动作数据和环境缓存。
- 修改后说明改动、验证结果和未解决问题。
```

## 5. 对你的仿真项目尤其有用的做法

**指定解释器和环境。** MuJoCo、mjlab、Isaac Lab 可能使用不同 Python 环境。提供已经验证过的启动方式，并要求先检查。历史排障记录只能作为线索，不能证明当前状态仍然相同。

**先读日志，再解释结果。** 报错时给出完整命令、工作目录、最后一段错误和日志位置。不要只说“跑不起来”；也不要让模型只凭截图猜原因。

**把耗时任务的边界说清楚。** 例如“只允许 100 个迭代用于测速，完成后停止并报告峰值显存与耗时”。这比“先跑一下看看”更容易控制成本。

**将修改与证据一起审阅。** 查看改动文件、运行命令、退出状态和输出路径。仿真能启动、策略能回放、论文结果复现是三个不同的验收层级。

**在权限不足时处理具体操作。** 能读取兄弟项目，不代表当前会话可以写入这些目录。如果要修改另一个项目，可以切换到对应项目继续，或按界面请求授权；不要用重新安装、删除缓存来代替定位问题。

## 6. 如何检查 Codex 的科研输出

建议每次检查五件事：

1. 文献标题、年份和链接是否对应，是否区分预印本与已发表版本。
2. “首次”“无人研究”“一定提升”等表述有没有充分证据。
3. 本地成绩是否有配置、日志和 checkpoint 支撑，而非来自上游 README。
4. 对照是否公平，是否同时记录环境交互、更新次数、运行时间和内存。
5. 结论是否来自真实仿真评测，而非仅来自世界模型内部预测。

Codex 可以协助检索、分析、修改文件和运行验证；毕业设计的研究结论必须由你能解释、能复查的证据支撑。
