# 申报表为什么这样修改

2026-11-10。当前采用修订内容，Word 分页尚未目视验证。报告见 [修订记录](../02_milestones/M00_proposal_revision_20261110.md)。

原表把串联腿、SuperMimic、实物全部通过和明显提升串在一起，但当前方向是完整并联轮腿的动力学适应与可微世界模型策略学习。已有控制基线不能证明学习模型有效，申报表应写拟研究方法和检验办法，而非提前写实验结论。

动力学上下文是从历史观测/动作推断的表征，不必与真实质量或摩擦一一对应；在线更新上下文不等于在线重训网络。可微指学习模型能传播梯度，不意味着 MuJoCo 接触和完整闭链求解器已经可微。模型预测误差下降也不保证策略改善，因此同时检查留出预测和控制表现。仿真特权状态可用于监督，但不能默认为实物策略输入。

关键改动在本次 revise.py 的 texts 和 setcell：五个研究栏目写成普通单元格段落，清除原浮动文本框，纠正栏目错位；不改变真实模型或控制程序。审批行保留原文件 XML，不将原有审批文字当作本轮获得的新批准。

复验只处理文档，不运行机器人：使用本次 manifest 中的 bundled Python 执行 `runs/m00_environment/proposal_revision_20261110/check.py`。正文/ZIP/源哈希检查通过。render_docx.py 对真实输出运行失败，具体错误见 render.log；内置渲染器依赖系统库版本高于宿主，不能据此归因于机器人环境或修驱动。未改系统库，未用系统 LibreOffice 替代。无法据此宣称分页、字形、跨页表格已验证。

适用范围是本次申报文案，不是算法验收。题目为申报建议，创新点仍需文献差异论证；数值阈值应在小试后、正式留出测试前锁定。下一步先在 Word 核对表格，再做研究问题收敛。
