# E003 从闭链接口到 PPO

E002 用经典反馈控制完整闭链。E003 复用相同的 XML、网格、初始姿态、六路驱动名称及腿长定义。四个前后髋和两个轮子是主动轴，其他转轴由机构及接触求解。四处 `connect` 约束两个销接部位上的对齐点，保留两侧闭链，不能从六路电机数量推断模型只有六个转动关节。

## 动作、观测与奖励

`task.py` 用 `XmlActuatorCfg` 绑定已有 motor，按关节名映射策略输出。±1 动作乘 XML 力矩限值，控制周期 10 ms，物理子步 1 ms。原生 XML 的 actuator 声明顺序与 mjlab 的关节顺序不同，单环境用六个不同的正负动作逐路检查，避免左右、电机和轮子串接。配平力矩只在接口验收中使用。

策略使用重力方向代理、IMU 加速度与角速度、主动髋角及编码器速度和历史动作。世界速度与髋轴到轮心的实际三维距离用于奖励及评测。实际姿态估计、传感器时序和噪声的影响仍待验证。

## Warp 约束容量与短训结果

首次建立动作管理器时，XML 范围来自 NumPy 双精度，Torch 目标缓冲区为单精度。将读取值转换为 Python float 后，动作检查通过。随后随机策略倒地出现更多接触，`njmax=96` 无法容纳约束行，日志报告至少需要 166，接着观测出现 NaN。当前把 `njmax` 提到 256，`nconmax` 提到 96，并从已有 checkpoint 恢复剩余预算。单环境复验和恢复短训通过。

PPO 的 rollout 长度与物理积分步不同。256 环境、24 个控制步、10 个子步合计每更新 61440 物理步。修复前后合计上限 983040 步。短训的角色是验证训练链路及暴露失效条件。最终留出测试 0/20，全部约 0.20 秒跌倒。失效原因尚未通过受控对照确认，下一轮先记录倒地前动作、腿长与接触轨迹，核对探索扰动和站姿附近支撑力矩。

从 E003 执行 `python -B run.py native` 与 `python -B run.py check --device cuda:0` 可复验模型接口。评测参数、命令与证据见[阶段报告](../02_milestones/M03_e003_ppo.md)。

## 课程预设与初始支撑

四个预设共用观测和动作维度，因此 RSL-RL 可以续载上一阶段的策略、价值网络与优化器。速度课保留部分零速命令，静止变腿长课混入标称腿长行驶，最后一课还保留静止变腿长。新站立策略将 actor 输出层的偏置设为原配平力矩除以各路限值，初始探索标准差由 0.35 降至 0.035。配平值只写入网络初始参数，运行时由网络直接给六路归一化力矩。首个新站立 checkpoint 的留出存活中位数由 0.20 s 增至 0.405 s，仍未达到站立阈值。两项初始化调整同时实施，当前结果无法归因到其中单项。

复验用 `python -B run.py train --preset stand`，后续预设以 `--checkpoint` 加载上一阶段。评测使用相同的固定留出种子。下一项最小诊断是对照配平输入与训练后输入，记录前 0.5 s 的实际六路力矩、两腿长度和接触演变。

## 纵向平移和偏航

上一轮短训会先出现两腿缩短、机身高度下降，再触发跌倒。固定配平力矩也只能在局部平衡点附近短时维持。E003 增加独立偏航角速度命令，以仿真速度反馈和跌倒惩罚帮助纯 PPO。备选控制在 100 Hz 用闭链 LQR 计算平衡力矩，PPO 输出六路限幅修正；轮轴方向相反，前进和偏航的轮速参考必须分别转换。三项评测和零残差对照见阶段报告。当前仅有平地纵向平移和原地偏航证据。
