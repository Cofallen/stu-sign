# 按住/释放、方向和参数接口

本轮用户要求释放即停止命令、前后反转、三倍速度、连续腿长/扩大范围、增高跳跃，并在 README 给接口和架构。当前说明以 [E002 README](../../experiments/E002_original_controller/README.md) 为准，旧锁存式描述是历史。

## 为什么不能只在 on_key 里把速度设为零

passive viewer 的 key_callback 只给按下，不给释放。旧代码累加 W/S 和腿长，因此松开后状态一直保留。用自动重复间隔猜释放也不可靠；原 pynput 未安装，项目规则又不允许为小问题修改既有环境。

当前 KeyboardInput 使用系统已有 libX11 查询实际位图。自有 viewer 的回调只绑定窗口并保存 J/X/R；物理循环每10步 poll 当前 W/S/A/D/Q/E。只有已绑定窗口有焦点才读这些键；失焦返回空集合。Teleop.set_pressed 每次都接收集合，即使为空也要传，才能触发制动/腿长保持。没有安装键盘库、记录其它应用的输入文本或改变全局键盘设置。

这是本机 Linux/X11 输入后端，不声称原生 Wayland/Windows 已适配。回调与物理线程用锁保护连接，关闭/无焦点也作检查，避免用失效 display 指针调用 Xlib。

## 方向、速度与“停止”各有不同含义

按用户指出的外观前方，将 W 的 forward_sign 从 + 改成 -；初始模型前方为 -X，S 为 +X。只改高层目标，不能同时翻转已经配套的电机/编码器/IMU，否则会破坏平衡反馈。

最高目标由0.4到1.2m/s，正好3倍；目标上升斜率0.5到1.5m/s²。释放的含义是立即取消运动命令、进入3m/s²目标斜坡制动；真实速度受惯性与平衡控制影响，不能把速度变量硬写成零。实测 ±1.176m/s，释放约1.47个仿真秒后实际速度持续低于.05m/s，后期峰值约.0062m/s。这里没有承诺瞬停。

仿真时间和墙钟时间必须分清。真实窗口有渲染/锁同步开销，本次按住5.1墙钟秒只推进了约1.71仿真秒；这不改变m/s参数，但会影响手感。应看 RUNNING 时间，关闭旧窗口以免多实例竞争。未通过改物理 dt/强写位置伪造三倍速度。

## 连续腿长与更高跳跃

Q/E 持续按住时按 `l0 += sign*l0_rate*dt` 变化，边界 .18–.34m、速率 .12m/s；松开时没有这项增量，因此保持当前目标。目标边界不等于瞬时实际值，PID需要跟随；短测实际短端约.180436m、长端约.339732m，误差均小于1mm。

J 为单次动作，方向键必须松开、速度接近零。下蹲.20m、蹬地.34m、额外每侧200N支撑、.40/.20s两阶段，随后恢复，总1.60s。相比上一版，下蹲更深、蹬地行程和时间更大；力仍由原VMC和六电机输出，±30/±5Nm限幅不变，不向基座加向上力。实测上升.22137m、双轮腾空.421s，较前版.127m/.24s增大并落地。

空中轮速里程计会失真，旧限制未解决；不能把跳跃稳定写成飞行状态估计完成。最高速度、腿长极限、跳跃是分项测试，不是任意高度/转向/速度组合都验过。

## 文件边界和推荐改法

- KeyboardInput：键位、焦点、释放、单次动作；不碰控制力矩。
- Teleop：用户目标、速度/制动斜坡、腿长积分、跳跃状态机。参数集中构造函数，用命名参数覆盖，不额外造配置框架。
- LQRController/VMC：六状态反馈、支撑与真实机构力矩映射。调交互不改K；改模型要重验，不把方向问题交给盲目翻转增益。
- controller.py：组装/循环；render_stand.py 显示；simulation.py 日志/验收。Python仍在一个文件夹，入口在外。

具体单位表、函数签名、调用例子和 Mermaid 控制链均写在 README 中。本轮四个12s物理时序试验通过；真实GLFW/XTest另发送了实际down/up并产生 w→空、s→空、q→空、e→空事件和增强跳跃，二者分别留证据。当前回归站立10s也通过。没有训练、实物或跨机结果。
