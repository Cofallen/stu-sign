# 从旧 LQR/VMC 到完整闭链站立

日期：2026-11-09。对应 [T003](../04_tasks/T003_parallel_standing.md)、[站立报告](../02_milestones/M02_parallel_standing.md)。这里解释过程和容易混淆的概念，最终数值以报告链接的原始 run 为准。

## 1. 为什么不能把旧 K 填进新模型

用户原仓库 `Cofallen/Leg_simulator_mujoco` 的 main 分支中，`LQR_six/lqr_controller.py` 用六个状态（腿角/角速度、位移/速度、机身角/角速度）算轮力矩和髋虚拟力矩；腿长 PID 加重力支撑，再通过 `vmc.py` 的运动学 Jacobian 映射到两腿电机。`lqr+mpc` 分支另有 `mympc.py`，原调用将 LQR 与 MPC 输出叠加。它们是用户原实现，不能称为本项目原创。

原代码的机身质量常量为 10 kg、轮径半径为 0.05 m，VMC 杆长为 0.215/0.258 m。当前正式 XML 总质量约 21.055 kg、轮半径 0.06 m，且有独立后支路、不同坐标与左右转轴。模型的 A、B、K 与 VMC 运动学必须配套；只修改质量或输出正负号不能保证平衡。读取 XML actuator/joint 的名字和地址比假设“前三个左腿、后三个右腿”可靠。

本轮保留状态反馈、支撑平衡和滚动优化的思想，**独立实现基于完整 MJCF 的仿真站立基线**。没有复制旧 K、杆长、质量、机器人或 VMC 源码；没有声称复现原六状态控制器。LQR 与 MPC 是两个可单独选择的模式，没有沿用旧混合输出比例。

## 2. 装配闭合与受力平衡是两件事

M01 的默认姿态闭环几何残差接近零，只证明销接点对齐。自由基座在重力下还需要：轮子落地、总质心位于可支撑位置、地面反力及六个驱动力矩抵消重力。固定基座/关闭重力的机构动画不验证这件事。

`src/wheel_leg/control/standing.py:solve_equilibrium` 分两步求 reset：先用所有原始连杆几何和四对闭环 site，求机身约 0.25 m、轮心接近半径高度、轮心 X 接近整机质心 X 的装配姿态；再固定横向基座坐标，优化高度、小俯仰、非轮关节角及六个电机力矩，使 `mj_forward` 的 `qacc` 接近零，并检查接触数和输入范围。

这里的 qpos 优化**只用于初始化**。开始积分以后，控制只写 `data.ctrl`，推力测试另写 `xfrc_applied`；不强写位置/速度、不固定基座、不焊死被动连杆。未增加任何执行器、支撑杆或额外接触。只允许六个原 actuator 生效。

静态闭环残差约数微米而不是几何 reset 的 1e-15 m，是受力时软约束产生的微小变形。MuJoCo 的 connect 和地面接触使用数值柔顺约束；必须同时检查最大残差、加速度和接触，不能要求既有有限接触承载又把每个软约束误差强行写为零。

## 3. 保留的失败尝试

早期原型对优化变量使用相对步长 `diff_step=1e-5`。某些被动角接近零，相对差分的实际扰动太小，数值导数不可靠；优化落到无接触、约 -9.78 m/s² 的自由落体状态。进程退出 0 不代表平衡成功。原型、重放日志和判定保留在 `runs/m02_standing/source_and_probes_20261109_135708_139243/`。

采用三点居中绝对差分后，无弹簧平衡最大加速度约 4.90e-6，能形成轮地支撑。正式入口第一次加入带输入边界的信赖域静态优化时，又落入高度约 0.871 m、无接触的解，达到迭代上限，明确拒绝并退出 2；见 `lqr_no-gas_20261109_135634_476468`。不是放宽成功门槛来接收它。

当前采用：无界优化静态力平衡，随后严格检查所得力矩在 XML 范围内、最大加速度 <0.001、至少两个接触；任一不满足就拒绝开始控制。运行时 LQR 限幅，MPC 在整个预测序列上施加输入范围。静态求解与动态安全范围各有独立验收。这个解法只对当前模型附近的支撑姿态有效，未证明任意初始配置都会收敛。

## 4. 为什么状态是 37 维，不是 37 个物理自由度

完整模型 nq=21，包括自由基座四元数；nv=20，是自由基座 6 个速度加 14 个树形铰链速度。四元数有四个存储分量、三个旋转自由度，所以姿态误差必须用 `mj_differentiatePos`，不能直接做 21 维 qpos 相减。

先形成 20 维切空间位置差与 20 维速度。横向绝对位置、左右轮绝对相位是此局部站立任务不反馈的循环坐标，因此去掉这三个**位置**，保留其速度，得到 37 维反馈状态。这样避免无目标的轮相位/侧向位置积分模态影响 Riccati 求解。37 维仍含闭链树形冗余坐标，不是 37 个独立物理自由度；没有把并联机构换成串联机构。14 个内部关节经 8 个独立闭环约束后是 6 个内部自由度，地面接触还会限制运动。

这是特权状态反馈：读取了仿真基座位姿/速度、被动关节等。真机 IMU/编码器并不自动提供全部这些量，`orientation` 的仿真真值也不等于实机姿态滤波器。下一阶段要单独实现和验证可部署状态估计，不能把此处状态名直接作为策略部署观测契约。

## 5. LQR 和 MPC 的具体计算

在静态接触点调用 `mjd_transitionFD`，对原始 1 ms `mj_step` 做居中差分，得到离散 A1、B1。控制周期是 10 ms，零阶保持提升为：

`A = A1^10`，`B = Σ(i=0..9) A1^i B1`。

`design_feedback` 对这套状态/输入求离散 Riccati 方程，反馈为 `u = u_ref - K e`，再按命名映射到 XML 顺序。Q 着重限制基座 X/Z、roll/pitch 和腿角，R=0.1 I；完整对角权重、A/B/K/P 和平衡点写入每次 run 的 `design.npz`，执行源码另做快照。闭环谱半径 <1 只说明局部线性化，不替代非线性仿真。

MPC 使用相同 A/B/Q/R，预测 N=15 步（0.15 s），末端代价 P 来自 LQR。优化的是电机力矩偏差 Δu，所有预测时刻均要求 `ctrl_min-u_ref <= Δu <= ctrl_max-u_ref`。先求无约束二次型解；整个序列满足边界就直接采用，否则用 SciPy L-BFGS-B 解凸二次问题，每次只执行第一个输入、下次重新预测。源码有显式 LQR 限幅回退；发生一次求解失败就会计数，并让该次验收失败，不把回退藏成 MPC 成功。

带 LQR 末端代价的线性 MPC，在约束不激活时应与 LQR 等价。`check_design.py` 对全部 37 个小误差方向检查这一数学性质，并用 0.1 rad 俯仰误差检查真正的输入约束分支、预测序列边界及投影梯度。仅输出第一步做 clip 的方法不等于整个预测序列都受约束；本实现区分两者。原仓库 `mympc.py` 的“无约束求解后裁剪首步”属于其原实现，不把该差异写成本项目复现结果。

## 6. 运行、判断和适用范围

项目根目录运行：

```bash
PYTHONNOUSERSITE=1 /home/cofallen/miniconda3/envs/mjlab/bin/python -B scripts/m02_standing/run_standing.py --duration 10 --cases nominal
PYTHONNOUSERSITE=1 /home/cofallen/miniconda3/envs/mjlab/bin/python -B scripts/m02_standing/run_standing.py --controller lqr --duration 30
PYTHONNOUSERSITE=1 /home/cofallen/miniconda3/envs/mjlab/bin/python -B scripts/m02_standing/run_standing.py --controller mpc --duration 30
```

`--variant gas` 单独求该等效弹簧版的平衡点和增益；不是把无弹簧 K 当成已验证通用 K。`--viewer --cases push --duration 30` 在用户桌面打开实际实时仿真；`--video` 用 Mesa CPU 离屏渲染并保存 mp4。当前会话只实际验收无窗口积分和离屏录像，原生 GUI 是否能打开另列未验证。

一次运行一个新目录，输出实际执行参数、解释器/版本、XML/网格/代码哈希、源码快照、日志、退出码、平衡点与设计、100 Hz 完整状态和力矩、每个案例的最大指标。`terminated` 是跌倒/无效数值等提前结束；`timeout` 是达到设定评测时长，后者对本任务是成功所需条件，不能当作摔倒。

本轮验证固定模型、平地、附近 reset、小扰动。初步使用的 +0.03 rad 是开发回归案例；-0.03 rad、推力、侧倾为随后检查案例，不可宣传为统计泛化率。气弹簧仍是未标定的等效空间 tendon，STL 视觉不随长度发生真实套筒伸缩；支撑力矩降低不证明真实气弹簧辨识正确。没有训练、GPU/Isaac 或实物结果，也没有起身、行走、跳跃或大范围抗扰保证。

实际约束优化检查：37 个小误差方向上 MPC 与 LQR 的首步输入最大差约 3.25e-19 N·m；0.1 rad 静态误差测试的整段输入越界为 0，投影梯度无穷范数约 1.23e-6。随后 30 s 的 `pitch-large` 实际积分通过，约束求解 2 次、失败 0 次；最大闭环残差约 3.39 µm、最大位移约 1.84 cm。但该案例最慢控制调用约 41.29 ms，大于 10 ms 控制周期。离线积分会等待求解完成，未模拟通信延迟和错过截止时间；不能把这种成功解释成硬实时控制成功。默认 LQR 的优势在于计算简单；MPC 若走实机路线，下一步应固定求解器预算并加入实际延迟评测。

## 7. 用户要求后的独立目录整理

此前站立实现分散在 src、scripts、assets，符合当时公共分层但不便只复制一个小目录。用户新增《项目结构规范.md》后，当前采用 `experiments/E001_parallel_standing/` 的独立副本；不移动/删除原工程目录，也不改历史 run 的绝对路径。两种交付分别追溯：旧 M02 是当时的集成实现与 18 个案例；E001 是现在整理的独立实验及本轮复制检查，不能互相冒认成绩。

小目录只有本地 standing.py、仿真入口、两个实际检查/汇总脚本、模型和说明。控制器文件保持逐字节相同；入口的 ROOT 改为自身所在目录，`from standing import ...` 使用同目录模块，没有向父工程插入 sys.path；资源直接读本目录 assets，输出写本目录 outputs。默认入口改成 10 s nominal，完整 30 s 案例仍通过显式参数选择。参数默认值变化与控制算法变化要区分。

“复制成功”不能只看 Python 文件能 import：XML 引用的 24 个 STL 也是依赖，全部原样携带两份正式模型、原 manifest；外部解释器、MuJoCo/SciPy 等库和 ffmpeg/图形后端只列明依赖，不复制整套 conda 或安装其他包。source manifest 中保留源路径是为了追溯，不代表运行要读取那些历史位置。旧实验结果用索引引用，未复制成两套可修改的历史证据。

实际复制验证必须从新目录之外启动，检查运行 metadata 中解析出的模块/XML/outputs 路径在副本内，比较复制前后的保护文件哈希和原轨迹前缀。这里只做原有短案例，不借结构整理启动长训练。strace 的 ptrace 在沙箱不可用，原失败日志保留；替代的 Python open 审计可以拒绝原工程路径，但不覆盖原生 C 库全部文件调用，因此报告不会将它写成操作系统级隔离证明。完整结果与命令见 [独立验证报告](../../experiments/E001_parallel_standing/REPORT.md)。
