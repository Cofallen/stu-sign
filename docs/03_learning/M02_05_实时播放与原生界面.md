# 实时播放、原生视角与输入查询

现象：仿真目标速度已是1.2m/s，画面仍像慢动作。速度单位是每模拟秒，而模拟秒不一定等于墙钟秒。RTF=模拟时长/墙钟时长；本轮提前定义.95–1.05为短测近实时，不能靠放大dt或提高驾驶速度修复播放倍率。

采用方案：入口controller.py保留1ms物理/原控制；显示每33步约30Hz用sync(state_only=True)，启动才全量同步一次；HUD默认关闭，开启时墙钟最多10Hz且最终字符串去重。节拍以perf_counter测量，快则sleep，慢则记录落后，不跳过物理步。render_stand.setup_viewer设FREE自由相机与原生面板，只设初始合适距离；TRACKING需显式--camera-follow。自由视角走出画面应移动视角，不能当作机器人不动。原生界面不代表passive viewer具备完整simulate的暂停/模型编辑语义，积分仍属Python。

失败与依据：P0静止RTF.99971，但真实驾驶只有.51458，不能拿静止成功覆盖失败；仅修热键局部抓取仍.44993。无真实键的同运动时序.99989，说明运动本身不是充分解释。cProfile尝试因入口os._exit不生成pstats，不能据此宣称函数级耗时。将X11等待移到后台线程后，真实键驾驶达到.99247；这是受控改动的证据，并非所有硬件都由同一原因造成卡顿。

KeyboardInput用_NET_WM_PID确认本进程窗口，查询焦点与公共viewport中的鼠标位置。只有三维区驾驶键被局部抓取，避免W/J/X等原生显示快捷键被同时触发；不是周期性覆盖显示flags。鼠标到侧面板或失焦时返回空按住集合，恢复原生操作；--no-drive完全关闭驾驶输入。后台独占X11连接，主循环poll只取缓存与累计动作，不阻塞积分；刷新周期10ms加显示服务器响应，不保证极短点按，J/X/R建议正常点按至少50ms。关闭时线程结束、释放本窗口抓取和连接，不改全局键位或安装输入库。

物理步长、额外mj_forward、VMC的pinv、LQR、Teleop参数都没改；10s headless trace与上一版逐值一致，资产/控制模块hash一致。没有为了优化引入P1几何缓存或改变反馈时序。默认HUD与跟随可选项见E002 README，源码仍一个根入口+LQR_six，不重排目录。

最终真实窗口含鼠标旋转/移入面板制动/跳跃/HUD：14模拟秒/14.00197墙钟秒，RTF.99986；相机角度改变保留，驾驶不改显示flags。--no-drive下原生W/J仍改变显示且持久，证明确实尊重界面选择。最大短时落后.164s，不是1ms硬实时保证。完整失败、命令、版本、截图与证据索引见[E002报告](../../experiments/E002_original_controller/REPORT.md)，[自动汇总](../../experiments/E002_original_controller/outputs/realtime_validation_20261109_200238_639594/results.json)。

复验在E002目录，用现有mjlab解释器 `python -B controller.py --viewer --duration 14`；点击聚焦、鼠标在三维区按住W，松开制动、停稳J，鼠标左旋/右移/滚轮缩放。--no-drive检查原生快捷键；--hud检查低频文字；--headless --duration 10回归。依赖现有MuJoCo3.11.0/libX11，未装新库。仅本机Linux/X11、无弹簧平地短测；未验Wayland/Windows、长期、gas混合驾驶、实物/训练。下一项最小任务是30s混合动作及墙钟落后检查。
