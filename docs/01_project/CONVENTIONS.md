# 目录、实验与引用规范

新增小实验的集中组织、独立输出和可复制交付，以根目录[项目结构规范](../../项目结构规范.md)为准。既有与正式集成代码仍按下述目录管理；历史记录不迁移、不改写。小项目 outputs 同样遵守一次运行一个新目录及来源/验收记录要求。

## 1. 分层原则

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| 根目录 README | 项目入口、当前范围、已验证命令 | 大段原始日志 |
| 根目录 AGENTS | 后续工作必须遵守的项目约定 | 某一次实验的临时假设 |
| `docs/00_context/` | 原始选题稿、历史说明、本机手册 | 当前实验成绩覆盖旧文 |
| `docs/01_project/` | 当前总览、规范、目录迁移记录 | 每次运行的全部输出 |
| `docs/02_milestones/` | 每个阶段的结论、验收、限制、命令与证据链接 | 未实施框架冒充完成交付 |
| `docs/03_learning/` | 关键操作的原理、代码定位、可复验学习笔记 | 只写“改好了”或把近似实现写成真实硬件 |
| `scripts/mNN_name/` | 对应阶段可直接执行的入口 | 上游训练代码副本 |
| `src/wheel_leg/` | 后续实际实现的共享任务、后端和算法模块 | 为每次实验复制一套库代码 |
| `assets/robots/<version>/` | 指定来源的派生资产、生成配置、manifest | 来源或版本不明的模型 |
| `upstream/<repo>/` | 固定 commit 的原始仓库 | 本项目日常修改 |
| `references/` | 来源登记、BibTeX、许可文本 | 模型、数据或论文成绩的无来源摘抄 |
| `runs/mNN_name/<run_id>/` | 原始运行证据，包括失败 | 手工覆盖、修饰后的原始数字 |

阶段号使用固定宽度 `m00`、`m01`；阶段报告使用 `M00_...md`、`M01_...md`。命名优先说明用途。只有某目录确实有实现或交付时才创建，不预建所有技能的空框架。

## 2. 按进度推进

M00 环境 → M01 模型 → M02 最小任务 → M03 PPO → M04 MuJoCo actor → M05 世界模型命令任务 → M06 参考动作与比较；Isaac Lab 验证和后续复杂技能分别列明状态。

每份阶段报告使用统一内容：目标与范围、输入来源与版本、实现及差异、实际命令、验收阈值与结果、未验证/阻塞项、下一项最小任务。模型分支应分别验收，例如“标准 V4 简化模型通过”不代表“并联结构通过”。

状态采用：未开始、进行中、通过（明确范围）、部分通过、阻塞。阻塞项写具体条件；不把阅读完成当作算法复现完成。总览是当前状态入口，历史报告保留当时语境。

## 3. 运行记录

运行 ID 使用 `<purpose>_YYYYMMDD_HHMMSS_microseconds`，时间为 Asia/Shanghai。目录创建时拒绝覆盖已有目录。当前检查脚本已按阶段输出；历史证据通过 `runs/INDEX.md` 定位。

最低记录：命令、cwd、解释器、依赖版本、源 commit/哈希、配置、退出状态、日志、结果文件和成功判据。训练增加种子、环境交互数、总墙钟时间、模型/策略更新成本、显存、checkpoint 与留出评测。版本快照不能直接称作可重建依赖锁；重建锁还需说明 wheel/驱动与 editable 改动。

运行记录采用三个层次：原始证据保存在 run 目录；阶段报告解释结果；总览只列结论与指向证据的链接。失败、迭代与验收采用记录分别标明，不删除失败来制造“首次成功”。

历史记录中的绝对命令路径可以在迁移后失效，保持原文；使用当前 README 命令重跑。`folder_migration.json` 记录本次移动及移动当时 SHA256；脚本与文档的后续内容更新不回写该历史哈希。

## 4. 开源参考与学术引用

每个新增外部来源记录：名称、原始 URL、作者/维护者、采用的 commit/tag/版本、访问日期、用途、实际复用的文件/模块、许可证证据和本地修改。仓库级来源写 `references/sources.json`，人可读说明写 `THIRD_PARTY.md`。

- 论文：使用原论文/作者项目页；BibTeX 放 `references/references.bib`。只读摘要就明确标注，不据此写全文复现结论。
- 作者代码与第三方复现：分别登记，不能因项目名相同就合并归属。
- 资产：源模型、mesh、质量惯量和生成派生物分别追踪；manifest 写源哈希、生成过程与输出哈希。
- 代码：实际复制或改编时保留原文件版权与 SPDX，在登记中说明文件范围；仅阅读参考不写成“本项目使用其训练实现”。
- 依赖：安装使用、源码阅读和复制修改分开说明；依赖包许可证不自动覆盖其附带的全部第三方资产。
- 未确认许可：写明具体范围与缺失证据；不把文章许可套给仓库所有文件，也不自行加 MIT/Apache 掩盖来源。
- 论文结果、本地测试和方法假设分开标注；不使用未经验证的首次、零失败、免奖励或加速倍率结论。

对外发布前按实际采用文件再次核对授权和 attribution。此项是发布准备内容，不阻止当前已授权的本地只读审计和可逆实现。

## 5. 数据和接口版本

后续共享任务定义、ReferenceMotion 和 actor 推理元数据分别使用 schema_version。记录单位、坐标、四元数顺序、关节名与顺序、动作/观测缩放、控制周期、归一化和历史缓存。改语义时升版本，不只改网络文件名。

来源不明、动力学不可行或与评测条件不符的参考动作不得标成验证通过。新增技能优先增加数据与配置，但专用初始化、奖励与终止逻辑仍需单列。

## 6. 关键操作与学习笔记

用户要求记录关键操作以便学习。每次涉及模型结构、资产转换、控制语义、数值设置、训练方法、导出或重要排障时，同步更新 `KEY_OPERATIONS.md`，并在 `docs/03_learning/` 创建或扩展对应阶段笔记。普通格式调整不必单独写长篇笔记。

笔记至少说明：问题现象 → 证据与定位 → 为什么采用该方法 → 涉及文件/函数/参数 → 实际操作或代码片段 → 验证命令和真实结果 → 局限与未确认项。引用代码应使用相对链接和稳定的函数名定位，避免移动文件后只剩失效的行号。

索引中分别标记“当前采用”“历史尝试”“已撤回”。发生纠正时保留错误及原因，再指向新方案；不要将探索过程改写成从未出错的教程。笔记中的参数注明单位及来源，实测值与演示值分开，运行命令写明是否会重建资产或消耗训练资源。

阶段报告回答“交付是否通过”，学习笔记回答“为什么这样做、怎样复现”，原始日志继续放在 runs。只更新文档时检查链接和代码一致性，不重复启动训练。

## 7. 长期维护与任务协作（2026-11-09 更新）

[工作区使用手册](WORKSPACE_GUIDE.md)说明目录用法和跨窗口交接。[任务看板](../04_tasks/README.md)提供任务入口，每个任务的负责人、状态、修改范围和交接记录仅在对应卡中维护。README 不再复制阶段状态表，overview 是唯一当前进度总表。

本轮依据用户的 A+B 融合意向，将未来 M05–M08 调整为固定世界模型、动力学适应、模型内策略学习、实物与论文评测。第 2 节中的旧 M06 参考动作路线是此前规划；当前阶段安排以 overview 为准。原始历史报告不改成新标题，不据规划变更声称实现已完成。

新目录职责：docs/04_tasks 保存实际任务卡；未来 src/wheel_leg 保存本项目可复用实现，configs 保存可复用配置，data 保存版本化共用数据集，deliverables 保存冻结交付。后三者按实际需要再创建。scripts 仍是执行入口，runs 是执行证据，upstream 是未改动的外部源码。

跨窗口改公共文件、占用同一 GPU/实物或重建同一模型目录前协调；人工认领不等于原子锁。结束前补齐卡中证据与下一步，汇总窗口再更新总览。仅整理文档不重启训练。
