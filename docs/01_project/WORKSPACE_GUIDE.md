# 工作区使用手册

新增独立小项目按根目录[项目结构规范](../../项目结构规范.md)执行：文件集中于 experiments，自己的运行输出进入其 outputs，复制验证不隐式依赖主工程。已有项目级入口和证据继续通过 scripts、runs 查询。

本项目按“本项目实现、外部参考、执行证据、解释文档”管理。目录路径保持稳定，避免每次选题调整都重写脚本、资产和历史日志。

## 1. 信息各有一个负责位置

| 信息 | 唯一负责位置 | 更新时机 |
|---|---|---|
| 当前目标、已验证事实、阶段状态 | [overview.md](overview.md) | 方向变化或阶段证据确认后 |
| 某项工作的状态、负责人、交接 | [对应任务卡](../04_tasks/README.md) | 开始、关键进展、暂停/交接、完成 |
| 运行原始数字与文件 | 小项目用 `experiments/<小项目>/outputs/<新运行ID>/`，项目级运行用 `runs/<阶段>/<新运行ID>/` | 每次执行新建 |
| 对结果的结论与限制 | `docs/02_milestones/` | 完成一组检查/实验后 |
| 原理、操作过程与纠错 | `docs/03_learning/` | 关键操作后 |
| 论文/代码来源与版本 | `references/sources.json` 等来源清单 | 新引入来源时 |

README 只导航，任务看板只列任务入口。它们不复制实时状态。阶段报告保存当时结论，历史报告不冒充最新状态。

## 2. 文件放哪里

| 你准备新增的东西 | 放置位置 | 例子/边界 |
|---|---|---|
| 当前工作计划/接口决策 | `docs/01_project/` | 只有当前采用方案在总览登记；旧方案注明被替代 |
| 一个能独立交接的任务 | `docs/04_tasks/Txxx_用途.md` | 写清交付、范围、负责人、下一步 |
| 新小项目的代码、入口、配置及所需资源 | [experiments/](../../experiments/README.md) 下各自的目录 | 实验说明与启动命令写进各自 README |
| 项目级检查或正式集成入口 | `scripts/mNN_阶段/` | 入口负责参数/调用，不复制整套算法 |
| 可复用模型/算法/数据读取 | `src/wheel_leg/`，实际开发时创建 | 按职责扩展，如 models、adaptation、learning、data、backends；不按论文复制多套项目 |
| 可重复使用的实验配置 | `configs/`，实际需要时创建 | baseline/方法配置，配套版本与单位；当前未创建 |
| 机器人正式派生资产 | `assets/robots/<明确版本>/` | 当前 `infantry_parallel`；来源与生成方法随资产保存 |
| 项目级运行的输出 | `runs/mNN_阶段/<新ID>/` | config、metadata、日志、结果、checkpoint、视频 |
| 多次实验共用的数据集 | `data/`，实际采集时创建 | raw 原始数据保持不变；processed 写派生版本与划分清单；不把 runs 整体当训练数据集 |
| 最终冻结的交付包 | `deliverables/`，首次交付时创建 | 模型/策略版本、推理契约、评测摘要；由具体 run 追溯来源 |
| 下载的论文和阅读资料 | `references/` | PDF、BibTeX、来源、许可；简历属于个人资料 |
| 下载的外部源码 | `upstream/` | 固定 commit 的阅读基线；本项目改编进入 src/scripts 并登记归属 |

新增功能先按小项目落地。例如动力学适应验证的代码、配置和运行结果先放同一个实验目录。确有跨项目共享或正式集成需求时，再决定共享文件的落点。

## 3. 启动和查结果

- 小项目：打开各自 README → 执行项目内入口 → 查看该项目的 `outputs/`。
- 项目级工具：打开 [scripts 索引](../../scripts/README.md) → 执行所需的环境、模型或站立基线脚本 → 按 [runs 索引](../../runs/INDEX.md)或脚本输出查找记录。
- 外部实现：从 [upstream](../../upstream/README.md) 阅读原始源码。实验中实际采用的代码按来源规范登记。

## 4. 多个窗口的开始和结束

这些文件位于同一个磁盘工作区；不同聊天会共享文件，但不会自动共享对话记忆。

每个窗口开始时：

1. 读根 README、AGENTS、overview 和任务看板；不要只依据聊天中的旧计划。
2. 打开自己负责的任务卡，确认依赖、负责人、允许修改范围。
3. 若任务无人负责，在卡中写负责人（可用聊天名/任务名）、状态“进行中”、带时区时间，然后重新读取，确认没有冲突认领。已有负责人时先交接；不能因为时间久就自行接管。
4. 工作仅限卡中范围。需要改范围或公共接口时先在卡里记录影响，协调相关窗口。

结束或交接时：

1. 卡中写改动文件、实际命令/证据、已完成和未确认项。
2. 写一个接手人能直接做的下一步；中断也保留失败信息。
3. 状态设为待复核/已完成/待继续，并明确负责人是否释放。
4. 阶段结论由一个“汇总窗口”更新 overview；其他窗口在任务卡提供可合并结论。

任务卡是人工协作约定，不是原子文件锁。认领竞争或同文件重叠时必须协调，不能声称文件系统会自动防冲突。必要时顺序执行；本项目当前也未假设已经拥有可用的 Git 分支/合并流程。

## 5. 共享文件与实验设备

- `overview.md`、AGENTS、CONVENTIONS、来源登记等共享文件同一时间只安排一个窗口写。其他窗口把更新请求放进自己任务卡，交给汇总窗口合并。
- 同一模型生成目录也只由一个窗口写；检查窗口不能在另一个窗口重建 XML 时读取“半成品”。
- 每次执行都用独立 run 目录。共享数据集由一个采集/处理任务负责，后续只读固定版本。
- GPU/Isaac 实例、实物通信口/电机控制先在任务卡登记占用，同一设备的冲突工作顺序运行。登记只是协作约定，并非技术互斥锁。
- 训练与实验需按项目授权推进；排进任务卡不代表已经运行。

## 6. 变更和归档

路径重命名前先查脚本、Markdown、JSON 和 manifest 引用，保存迁移前版本和哈希；改活动入口，保留原始运行 metadata。迁移清单说明旧→新关系，不把历史路径偷偷改成今天路径。

本轮只重整说明、任务导航和当前方向，没有搬动 scripts/runs/upstream 中既有内容。旧目录名继续可用。未来若真实迁移，以迁移清单为准。

不要因某个教程在运行记录中提到命令就直接执行；以当前脚本索引、任务卡和环境手册为准。只有文档整理时检查链接即可，无需重新训练。
